# Native Android AdMob Integration Guide

This app cannot add native Android dependencies from the Base44 builder itself —
the Android project is generated by the platform (Publish → Mobile app → Create
Google Play files). Use this guide plus `admob.config.json` (same folder) and
`src/lib/nativeAds.js` / `src/lib/admobConfig.js` in the web app to wire real
AdMob into the generated project.

**Package name limitation:** Base44's generated Android bundle uses the package
`com.base[app-id].app`. A custom package such as
`com.masterpiece.wallpapers.ai1` cannot be set through the standard flow —
request it via support if the AdMob app must be registered under that exact
package.

## 1. Gradle (app module)

```gradle
dependencies {
    implementation 'com.google.android.gms:play-services-ads:23.6.0'
}
```

## 2. AndroidManifest.xml

```xml
<application ...>
    <!-- AdMob App ID (test app ID ca-app-pub-3940256099942544~3347511713 in debug) -->
    <meta-data
        android:name="com.google.android.gms.ads.APPLICATION_ID"
        android:value="ca-app-pub-6387191957285572~4480199819"/>
</application>
```

## 3. Initialize once (Application class)

```kotlin
MobileAds.initialize(this) // native runtime only — the website never calls this
```

## 4. WebView bridge (MainActivity)

Inject the JS interface before loading the app URL:

```kotlin
webView.addJavascriptInterface(AdMobBridge(this), "MasterpieceNativeAds")
```

`AdMobBridge` must implement exactly (IDs read from `admob.config.json`,
switching to the test units when `BuildConfig.DEBUG`):

```kotlin
class AdMobBridge(private val activity: MainActivity) {
    @JavascriptInterface
    fun init(appId: String, bannerId: String, interstitialId: String, rewardedId: String, debug: Boolean) { ... }

    @JavascriptInterface fun showBanner() { ... }   // adaptive anchored AdView, TOP placement
    @JavascriptInterface fun hideBanner() { ... }
    @JavascriptInterface fun showRewarded(requestId: String) { ... }
    @JavascriptInterface fun showInterstitial() { ... }
}
```

Report events back to the page with `evaluateJavascript`:

| Event | Call |
|---|---|
| Reward earned | `window.__masterpieceAds.onRewarded('<requestId>', true)` — fires ONLY from `onUserEarnedReward` |
| Rewarded dismissed (no reward) | `window.__masterpieceAds.onRewardedDismissed('<requestId>')` |
| Rewarded failed to show | `window.__masterpieceAds.onRewardedFailed('<requestId>')` |
| Banner height changed | `window.__masterpieceAds.onBannerHeight(<pixels>)` |

## 5. Placement rules (enforced by the web app, keep consistent natively)

- **Banner** — adaptive anchored, top of screen; the page pads itself using the
  reported height, and the bottom tab bar is never covered. Free users only;
  `hideBanner()` is called when premium activates.
- **Interstitial** — shown only by `window.__masterpieceAds`-side throttled
  calls at natural breaks (e.g. after deleting a wallpaper); never at launch or
  during generation.
- **Rewarded** — required before free generation/download; the gated action is
  granted ONLY from the earned-reward callback.
- The website (`masterpiece-wallpapers-ai.base44.app`) runs no AdMob SDK code;
  its simulated placeholder ad gate is bypassed automatically on native.

## 6. Google Play Billing (Premium subscription)

The Android app must use Google Play Billing for Premium. The website continues
to use Base44/Wix checkout. The permanent Play product ID is
`masterpiece_premium_monthly`.

Add the current Google Play Billing dependency to the app module and inject a
second JavaScript interface before loading the app URL:

```kotlin
webView.addJavascriptInterface(
    MasterpieceBillingBridge(this, webView),
    "MasterpieceNativeBilling"
)
```

The bridge exposes:

```kotlin
@JavascriptInterface
fun launchSubscription(productId: String)
```

Requirements:

1. Query `ProductDetails` for `masterpiece_premium_monthly` as a `SUBS` product.
2. Select the active monthly base-plan offer token and launch the BillingFlow.
3. On a successful `PURCHASED` result, call
   `window.__masterpieceBilling.onPurchaseCompleted(productId, purchaseToken)`.
4. Do not grant Premium in Kotlin. The web layer sends the purchase token to
   `verify-google-play-purchase`, which verifies it with Google before granting access.
5. On cancellation call `window.__masterpieceBilling.onPurchaseCancelled()`; on
   other errors call `window.__masterpieceBilling.onPurchaseFailed(message)`.
6. Acknowledge verified purchases using Google Play Billing. Restore purchases
   on app launch and send active subscription tokens through the same verification path.

The Base44 secret `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` must contain the Google
Cloud service-account JSON whose account has Play Console API access. Never
store that JSON, a private key, or purchase tokens in frontend or Android source.
